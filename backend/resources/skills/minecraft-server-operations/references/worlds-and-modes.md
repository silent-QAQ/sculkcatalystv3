# 世界、玩法模式、资源包与互通

## 世界管理

- 多世界先定义用途、边界、生成方式、权限和自动保存策略，再选择 Multiverse 等管理组件；世界名、目录名和玩家入口要保持可追踪。
- 新世界或大型地图先预生成（如 Chunky 路线），把生成成本放在上线前；预生成前评估磁盘、备份体积和时间。
- 调整视距、模拟距、区块卸载、世界边界和实体规则时一次只改少量参数，并记录对红石、刷怪、农场和玩家体验的影响。
- 重置资源世界、地图模板或区块前先停服/保存并做完整副本；CoreProtect 回档只适合可审计的局部破坏，不等同于完整备份恢复。

## 资源包、数据包和自定义内容

- 数据包改变世界机制，资源包改变客户端表现；安装、版本和作用范围要分开说明。
- 服务端强制资源包需要公网可访问 URL 和正确 SHA-1；大包会增加首次连接时间，应说明体积和 CDN/对象存储依赖。
- Terralith/Tectonic 等世界生成内容通常需要预生成和更高磁盘预算；升级或迁移时不要把生成中的世界强制中断。
- ItemsAdder、Oraxen、龙核等自定义物品/方块系统会同时涉及插件配置、资源包和客户端缓存，改动后要验证资源包下载、物品渲染、重启和回滚。

## Geyser / Floodgate

- Geyser 可以作为后端插件、代理插件或独立代理部署；小规模可先用后端插件，大型群组优先评估独立代理或统一入口。
- 常见默认链路会涉及 Java TCP 25565 与基岩 UDP 19132；实际端口以当前配置和代理拓扑为准，防火墙必须分别放行并测试。
- Floodgate 的免正版验证能力会改变身份、权限和安全边界；确认 `online-mode`、代理转发、权限组、基岩玩家标识和密钥文件的组合，不要只复制默认配置。
- 连接失败按 DNS/端口/协议 → Geyser 日志 → Floodgate 密钥 → 代理转发 → 资源包/客户端版本顺序排查。

## 技术生存

- 技术生存依赖红石时序、随机刻、区块加载、刷怪、TNT 复制和光照等机制；任何 Paper 优化都可能改变设计假设。
- 插件生电优先 Leaves：在保留 Bukkit/Paper 插件生态的同时，尽量还原红石、生物、区块和其他原版机制。只有接受模组生态、追求纯机制还原时才选择 Fabric + Carpet；Folia/Luminol/Lophine 的多线程和优化要逐项验证，不应只依据 TPS 选择。
- 生电服务器需要单独记录机制兼容目标、允许的 Carpet 规则、玩家客户端辅助模组、预生成范围和备份频率。

## 模式决策

- Survival/SMP：稳定核心、保护/回滚、权限、性能和备份优先。
- SkyBlock：岛屿保护、等级、团队、访客权限和重置流程优先。
- RPG：内容链路和资源包优先，插件依赖、经济与性能逐层验证。
- 小游戏：快速重置、模板地图、低实体和低视距优先。
- 创造/建筑：地皮、保护、编辑权限和世界边界优先。
- PvP：低延迟、实体与区块控制、战斗相关插件兼容优先。
