# 日志与故障诊断

诊断只输出证据、根因、风险和外部执行建议，不实施修复、重启或回滚。

## 证据顺序

1. 确定当前启动周期或调用方提供的 baseline。
2. 找到最早的实质错误，区分根因和级联异常。
3. 关联 Java/Minecraft/加载器版本、插件模组依赖、端口、磁盘、内存、世界和最近变更。
4. 将历史 crash report 单独列出，不让旧事故自动污染当前周期。
5. 对每个结论给出文件、行号/偏移、时间、脱敏片段和置信度。

## 常见类别

- Java class version、缺类、方法签名与加载器不兼容。
- 插件/模组必需依赖缺失、重复 ID、错误平台或错误版本。
- 端口绑定失败、未知监听者或多个实例。
- `OutOfMemoryError`、GC 压力、native crash、线程死锁或 watchdog。
- 世界锁、区块/玩家数据损坏、磁盘满或权限失败。
- 配置解析、数据库连接、认证、代理转发和密钥不一致。

OOM 不是自动加内存的充分理由；需要区分容量不足、泄漏、视距/实体负载、模组行为和宿主限制。连续崩溃不能只建议重复重启。

## 结论格式

输出症状、直接证据、支持的根因或排序假设、替代解释、影响、阻塞性未知项、条件性建议、外部角色前置条件和验证方案。证据不完整时使用 `inconclusive`，不得包装成确定根因。
