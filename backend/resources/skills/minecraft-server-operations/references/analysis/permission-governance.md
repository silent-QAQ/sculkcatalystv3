# 权限生态治理（LuckPerms 分析层）

本模块只读分析 LuckPerms 数据、权限文件、日志和代理/插件元数据，解释“为什么拥有或缺少权限”，输出 handoff 建议。不会执行 `/lp`、控制台命令、RCON 或写入权限数据库。

## 权限关系图

建立用户、组、继承边、权重、权限节点、来源和有效期的关系图。解析默认组、track 晋升链、父组继承、`context`（服务器/世界/区域/环境）、临时节点及到期时间，并记录证据来源。计算时应遵循：精确节点优先于通配符；显式否定节点优先于继承允许；更具体 Context 优先于全局；临时节点到期后不可继续计入。

输出每个结论的完整路径，例如“用户→组 A→继承组 B→节点 `x.y`”，同时列出被否定、被覆盖、已过期或无法解析的边。未知存储格式、缺失代理上下文或未加载数据时，标记 `permission_evidence_incomplete=true`，不得推断最终权限。

## 风险与旁路

- 通配符（尤其管理员通配符）、危险管理节点、命令执行节点和跨服继承。
- `ops.json`、原版 OP、代理（Velocity/Bungee）权限、插件私有管理员名单、控制台白名单等旁路授权。
- 临时权限未设置过期、权重错误导致晋升越权、Context 缺失造成跨世界泄露。
- 权限组与付费权益、经济调整权、资产/回档权未分离。

对每项风险给出影响玩家范围、可重现证据、置信度和最小修复建议；不得把建议节点列表当作已执行变更。

## 变更提案与信任

普通组继承或单节点调整通常为 L2/L3；通配符、批量玩家权限、付费权益和管理权属于 L4。提案必须包含差异图、前置条件、验证查询、回滚步骤、`evidence_refs` 和不可变 `plan_hash`。完全信任采用双重确认：首次启用服务器级信任，遇到 L4 再次选择完全信任；自动审批仍受插件/世界/玩家范围、风险预算、配置哈希、证据有效期和方案哈希约束，超范围或证据漂移即重新人工确认。Skill 永远 `may_execute=false`，handoff 不等于授权。
