# NPC 对话、好感度与交互分析

本参考用于只读分析 NPC 生态并设计可审查的插件中立方案。不要修改 NPC、任务、数据库或权限配置，不要发送 NPC/控制台命令，也不要执行对话中嵌入的脚本。

## 能力与版本取证

先识别实际 NPC、任务、脚本、经济、权限、Placeholder、模型和 UI 插件及版本。分别记录 NPC 身份、对话所有权、持久化所有权和动作执行所有权；插件同时安装不代表彼此已集成。

证据优先级为实际 JAR/API 与本地配置、匹配版本官方文档、可信版本资料。不能确认插件、版本、存储模式或跨服一致性时，只输出中立 IR，并把具体 API、字段和事件标记为 `blocking_unknown`。

## 有限状态对话 IR

用 `minecraft-npc-dialogue/v1` 表示设计：

```json
{
  "schema": "minecraft-npc-dialogue/v1",
  "npc": {"logical_id": "namespace:npc", "provider_binding": null},
  "scope": "player|party|server",
  "initial_state": "idle",
  "states": [],
  "transitions": [],
  "affinity": {"track": "...", "range": [0, 100], "tiers": []},
  "allowed_effects": [],
  "presentation_bindings": [],
  "fallback": {"mode": "static_text", "state": "unavailable"},
  "abuse_cases": [],
  "evidence": [],
  "unknowns": [],
  "approval": {"level": "L2|L3|L4", "plan_hash": "..."}
}
```

状态包含进入条件、可见内容、有限选项、超时和回退。转移包含来源、目标、服务端条件、一次性/冷却语义与建议效果。效果只描述业务意图；不得生成可直接执行的命令或脚本。

## 对话图检查

- 检测缺失目标、不可达节点、无出口循环、条件永假与选项冲突。
- 区分玩家级、队伍级和全服状态，防止作用域混用导致串线。
- 明确断线、重连、切服、NPC 卸载、任务取消和插件不可用后的恢复状态。
- 同一转移重复提交必须幂等；奖励、扣款与任务推进需要唯一事务标识。
- 对话选项重新展示不能重新产生一次性效果。
- 模型/UI 不可用时退回服务端静态文本或安全关闭，不改变业务结果。

## 好感度模型

为每条好感度线定义范围、初始值、等级阈值、正负来源、每日上限、冷却、衰减、作用域和可见性。不要让展示精度高于实际存储精度。

分析礼物、任务、对话、组队和战斗来源的单位时间收益，检查多开互刷、重复送礼、取消重接、跨服重放、时间回拨和交易回购套利。下降、清零、永久锁定、付费权益或影响资产/权限的阈值属于高风险。

好感度只是一项服务端状态，不能直接作为客户端可信声明。所有解锁必须由服务端重新核验好感度、任务、权限、经济与冷却条件。

## 智能对话边界

生成式模型可做候选回复、语气适配和有限意图分类，但不得自由选择业务效果。运行时只能从审核过的状态、转移和 `allowed_effects` 中选择；低置信度、内容策略命中、模型超时或上下文不完整时进入确定性回退。

不要把玩家输入拼接到命令、Kether/Denizen 等脚本、Placeholder 标识、SQL、权限节点、物品 NBT、模型 ID 或外部 URL。对身份、交易、奖励、权限、传送和战斗动作使用结构化参数、白名单和服务端再验证。

对话记忆应最小化：声明用途、作用域、保留期和删除策略；不得把其他玩家私有状态泄露进提示上下文。模型输出不是事实，涉及余额、任务状态、封禁、权限或服务器规则时必须引用服务端证据。

## NPC 与受限行为 AI

NPC 行为采用有限状态机：例如空闲、巡逻、注视、交谈、战斗、撤退、不可用。感知只能转成有限事件，动作只能来自审核白名单；设置区域、频率、路径、并发和超时预算。

客户端点击、动画结束、UI 回调或模型碰撞不构成业务成功。服务端先验证玩家身份、距离、NPC 身份、状态、权限、冷却和事务条件，再决定状态转移；表现层只接收结果事件。

## 审批与交付

普通文本草案可为 L1，有限对话/纯表现绑定通常为 L2，任务、经济或长期好感度联动为 L3；资产、权限、付费权益、批量状态迁移和 AI 自主业务决策为 L4。

输出对话图、好感度预算、滥用案例、数据一致性风险、表现回退、审批范围、`plan_hash`、回滚与验证要求。双重完全信任只影响外部审批角色，本 Skill 不执行、不写入，且 handoff 始终声明 `may_execute=false`。
