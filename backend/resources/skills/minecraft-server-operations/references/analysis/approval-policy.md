# 审批与完全信任

审批决定方案是否可以交给外部执行角色继续处理，不授予本 Skill 执行能力。

## 风险等级

- `L0`：只读报告和补采证据建议。
- `L1`：纯外观、文本和无玩法影响的草案。
- `L2`：普通任务、UI、动画绑定和限定期限的玩法权限。
- `L3`：经济参数、权限组、核心任务、Boss 战斗时间线。
- `L4`：批量资产、权限通配符、付费权益、回档、稀有怪/Boss AI 接管。

## 双重完全信任

1. 服主启用服务器级完全信任。
2. 首次触发 L4 时，再次人工确认一个明确的 `trust_scope`。
3. 此后主 Skill 只能判断方案是否满足外部自动审批条件，输出 `eligible_for_external_auto_approval`。
4. 独立审批角色验证 scope 的权威来源和第二次确认记录后才能形成自动审批事实；执行角色再独立实施。

`trust_scope` 必须包含服务器身份、领域、插件、世界、玩家影响上限、数值/风险预算、有效期和排除动作。不得使用无边界的 `all=true` 代替范围。

## 自动审批条件

- 方案风险不高于已批准等级，且领域、插件、世界、玩家范围均匹配。
- 插件版本、目标文件哈希、资产哈希和规范化方案哈希未漂移。
- 证据仍在有效期内，没有阻塞性未知项。
- 回滚要求、验证窗口、停止条件和审计标识完整。
- 建议不包含 scope 明确排除的动作。

任一条件不满足即返回 `manual_review_required`。版本、哈希、授权策略或影响范围变化会使旧审批失效。

## 撤销和审计

服主可随时撤销 scope。自动审批记录至少包含 scope ID、方案哈希、规则版本、证据引用、批准时间和失效时间。不得把聊天中的模糊同意解释为完全信任。

调用方提供的 JSON 布尔值不能证明服主已经确认。主 Skill 不持有可信身份或签名密钥，因此其 eligibility 输出不是批准结果。
