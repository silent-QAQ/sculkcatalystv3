# 经济生态治理（分析层）

本模块只读取配置、日志、插件元数据、可用统计导出和经服主授权的只读账本快照，输出判断与建议。不会调用 `eco`、市场命令、RCON 或插件写 API，也不会修改余额、价格、税率或配置。所有建议都是 handoff，不构成执行授权。

## 能力与证据边界

先识别 Vault 版本、实际 Economy Provider 及其数据后端，再识别市场插件（例如 QuickShop、ShopGUIPlus、EconomyShopGUI、AuctionHouse）和其他货币（PlayerPoints、VaultUnlock、CMI/XConomy/TNE 等）。Vault 只提供统一接口，不能单独证明总货币量、交易历史或净发行量。

证据按强度分级：

1. **强**：Provider 导出的只读账本/交易流水、数据库只读副本、带时间戳的统计 API 输出。
2. **中**：插件配置、日志中的交易事件、离线玩家余额快照。
3. **弱**：单个玩家余额、商店标价、文档示例或缺少时间窗口的计数。

缺少强证据时必须标记 `data_capability=partial`，只能给出方向性风险；不得声称已计算净发行量、货币流速或全服分布。

## 宏观指标

- 货币存量：按货币类型、世界和时间点统计余额总和，并注明是否覆盖离线账户。
- Source/Sink：在相同时间窗内分别汇总任务、掉落、出售、转账铸币（Source）与购买、手续费、修理、传送、税费、销毁（Sink）；净变化应与账本快照交叉验证。
- 通胀：构建稳定商品篮子 CPI，记录基准期、样本量、成交价而非仅标价；报告环比/同比和置信度。
- 分布：活跃玩家余额的 Gini、Top 1%/10% 持币占比和新玩家购买力；说明活跃样本偏差。
- 流通速度：若有交易额与平均货币存量，估算期间流通速度；否则降级为未知。

任何指标都必须携带 `evidence_refs`、时间窗口、覆盖率、计算方法和未知项。

## 微观与套利分析

按商品/市场分析成交价、成交量、点差、波动率和来源结构，比较任务/刷怪/商店的每小时收益。重点寻找：无限买卖闭环、跨市场价差、机器人高频下单、对敲、异常转账、重复领奖、退款/断线回滚套利，以及多货币兑换绕过限制。建议采用单变量调控（奖励、手续费、回收价或产出上限之一），附影响范围、观察窗口、停止条件和回滚要求。

## 输出与审批

提案应包含 `assessment`、`recommended_actions`、`risks`、`verification_plan`、`rollback_plan`、`evidence_refs` 和 `confidence`。经济税率、奖励、余额批量处理属于 L3/L4；即使服主已启用完全信任，L4 仍需再次选择完全信任后才可自动审批。自动审批必须校验 trust scope（插件/世界/玩家/风险预算）、方案哈希、配置与资产哈希、证据 freshness 和无阻塞未知项；任一变化即失效。Skill 永远 `may_execute=false`。
