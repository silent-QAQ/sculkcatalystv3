# 备份与恢复评估

本 Skill 只检查现有备份、manifest、文件身份、时间点和恢复风险，不创建、移动、删除或恢复备份。

## 有效性

- 区分文件副本、操作备份、世界快照、数据库逻辑备份和整服备份。
- 检查 manifest schema、serverRoot、路径安全、数量、大小、SHA-256、时间点和完成标志。
- 世界备份覆盖主世界、下界、末地及平台实际关联目录。
- 数据库、权限、经济、领地和玩家状态可能位于服务器目录外，必须列为一致性边界。
- 未完成、未校验、从未演练或唯一副本不能表述为可靠恢复点。

## 恢复建议必须列明

- 精确范围、目标时间点和数据损失窗口。
- 停服需求和外部数据库的一致时间点。
- 将新增、覆盖或删除的路径。
- 恢复前保护与回退恢复本身的方法。
- 平台、Java、JAR、配置和数据库版本兼容性。
- 验证步骤和停止条件。

整服/世界/玩家数据覆盖、遗漏关联维度或数据库、跨系统直接覆盖平台定义、不可逆迁移及在线恢复都属于高风险或阻塞场景。

handoff 的 `rollback_plan.available` 只有在现有恢复点已实际校验时才能为 true；看到备份目录不等于可回滚。
