# 文件变更风险分析

本 Skill 只分析和决策，不执行文件写入。本页用于评估外部执行角色拟进行的修改。

## 必查证据

- serverRoot 和目标的真实路径、文件身份及链接/reparse 状态。
- 文件用途、所属组件、格式、编码、权限、SHA-256 和加载方式。
- 是否要求停服，以及目标是否会在退出时被服务器重写。
- 关联配置、数据库、世界、玩家数据和外部服务。
- 已存在且经过校验的恢复点；本 Skill 不创建恢复点。

## 风险分类

- 低：只读检查、语法验证、差异分析。
- 中：普通文本配置建议，范围明确且存在可验证回滚。
- 高：JAR、启动参数、权限、端口、认证、数据库、世界或玩家数据。
- 严重：唯一备份覆盖、整服/世界回档、批量玩家数据或不可逆迁移。

## 建议约束

- 推荐补丁绑定原文件 SHA-256，并保留未知字段、注释和局部格式。
- YAML、JSON、TOML、Java Properties 使用对应语义；NBT、MCA、数据库和 JAR 不作为文本编辑。
- 路径使用精确 containment；字符串前缀不算位于 serverRoot。
- 证据漂移要求重新分析，不能就近猜测。
- 高风险动作列明影响范围、停机需求、确认要求和回滚限制。
- 不输出 RCON、数据库、API、OAuth 或 webhook 明文凭据。

## 禁止建议

- 不建议 raw shell 字符串、跨根链接写入、在线修改游戏数据或热替换 JAR。
- 不建议用 `/reload` 或插件管理器代替必须的完整重启。
- 不建议在没有可验证恢复点时实施高影响变更。

最终报告必须写明：本 Skill 未修改文件，所有变更均为外部执行角色的条件性建议。
