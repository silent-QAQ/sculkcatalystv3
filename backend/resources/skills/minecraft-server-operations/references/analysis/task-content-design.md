# 任务内容设计与治理

任务系统同时影响留存、经济、权限、叙事和服务器负载。先定义玩家目标和约束，再选择 Chemdah 或其他任务插件的具体表达方式。

## 中立任务模型

每个方案至少包含：

- 稳定 ID、目标受众、任务类型、预计完成时间和可重复周期。
- 前置条件、阶段、Objective、完成条件、失败/取消/断线路径。
- 任务、NPC、世界、物品、权限、货币和对话引用。
- 奖励来源、价值估算、每日理论上限和经济预算。
- 幂等领奖键、队伍/账号作用域、冷却和跨服一致性策略。
- 可观测指标、停止条件、回滚要求和人工审批等级。

## 内容质量

- 新手任务一次只教授一个主要机制，并提供失败后的恢复路径。
- 日常任务避免机械重复，按玩法类型、地图区域和社交方式轮换。
- 剧情任务保证关键分支可达；唯一选择必须清楚说明不可逆影响。
- 团队任务明确贡献判定、离队、掉线、替补和奖励归属。
- Boss 任务用可见预警和可学习机制控制难度，不以不可读秒杀代替挑战。

## 经济约束

用预期完成次数乘以单次奖励估算总发行量，并与同期货币回收、活跃玩家数及商品篮子价格比较。没有交易账本时只能做上界估算，不能声称已测得通胀。

重点检查重复领奖、取消重接、多个任务共享同一事件、组队复制贡献、多账号转移和跨服重放。高价值奖励优先采用绑定物品、分阶段发放、限额或非货币权益，但仍需评估玩家公平性。

## 审批与执行边界

- L1/L2 可按服主预批准范围审查；经济、权限、核心剧情和 Boss 通常为 L3/L4。
- L4 自动审批要求服务器级完全信任后，再由服主对明确 `trust_scope` 二次选择完全信任。
- 授权绑定服务器、插件、版本、世界、玩家范围、风险预算、有效期和方案哈希。任一证据漂移即失效。
- 自动审批不是执行授权。本 Skill 只输出方案与 handoff；独立执行角色重新验证后实施。

验收至少覆盖正常完成、失败、取消、断线重连、重复事件、队伍变化、跨服延迟和并发领奖。上线后按预设窗口观察完成率、放弃点、单位时间收益、净货币发行和异常重复领取。
